# Architecture

- `unity/Assets/Runtime/Player` — input, movement, camera, battery, preferences, player state, wallet/trade/rescue, save control and session-only developer controls.
- `unity/Assets/Runtime/Interaction` — targeting, inventory identities, discovery placement, reveal/collection, find handling/physics, guided extraction and unique display.
- `unity/Assets/Runtime/Terrain` — finite signed density and immutable material fields, smooth surface-net meshes, adaptive dig adapter, boundaries and derived surface grass/daylight.
- `unity/Assets/Runtime/UI` — HUD and menu behavior (UI Toolkit under `UI/Toolkit`).
- `unity/Assets/Runtime/Persistence` — versioned whole-world snapshots, atomic disk storage, recovery and autosave.
- `unity/Assets/Runtime/Validation` — disposable validation adapters, not production mechanics.
- `unity/Assets/Scenes`, `unity/Assets/Editor`, `unity/Assets/Tests` — scenes, editor tooling and repository-owned checks. `unity/Packages/manifest.json` is the dependency source of truth.
- `unity/Assets/Plugins/Sirenix` — approved Odin Inspector/Validator in Editor Only mode; `Assets/Editor/Validation/MainGameValidation.asset` owns game-content scan scope. Odin's build automation runs that profile before builds; game persistence remains independent.

- `MainGame.unity` owns one player/menu root and world camera. `MainGameRoot` owns excavation, the permanent rim/boundaries, the generated lakebed environment and station anchors; there is no tool rig. Level-driven shovel/drill motions and their developer comparison share the existing player/terrain/grid pipeline.
- `DesktopInstance` reserves one Windows player before scene load; duplicate launches focus the existing window and exit. `WorldSaveStore` separately locks the profile. Saves live in `Application.persistentDataPath/Save` (Editor uses `EditorSave`); only current-format v11 saves are supported, with atomic replacement and a retained previous checkpoint. No previous-format readers or content aliases remain.
- `FpsPlayer` owns `CameraPreferences`, `InputPreferences` and `GamePreferences` (separate `Preferences/camera-v1.ini`, `input-v1.ini`, `game-v1.json`; `EditorPreferences` in the Editor). `GamePreferences` is the sole runtime display owner; `DesktopWindow` supplies native defaults.
- `FpsHud` owns the single UI Toolkit document with `GameHudView`/`GameMenuView`; one retained EventSystem routes menu input; no Canvas HUD.
- `TerrainVolume`/`ExcavationGrid` own removed volume and synchronously rebuild matching render/collision meshes. `TerrainMaterialSnapshot` owns immutable seeded material IDs on that same lattice; `GridSnapshot` shares them with the save worker. Adaptive brushes apply `EquipmentProgression.MaterialResponse` per sample; `FpsPlayer` applies contact cadence/fuel and `TerrainVolume.ToolCut` publishes committed feedback. Geometric winch/blast removal stays independent of tool resistance. `TerrainVolume` owns reusable Burst meshing/exposure workspaces. `TerrainChunkMesh` derives clay/rock weights in the third UV channel from the material halo, with soil as the remainder; its density cache also tracks immutable material identity. `SiteLayout` owns the grid size, plot outline and find footprint. `ExcavationDaylight` and `SunPresentationSetup` derive presentation without excavation authority and save no lighting state.
- Approved vendor content stays under `Assets/BK`; game material and texture overrides live under `Assets/Content/Nature` and `Assets/Content/Lakebed`. `NatureEnvironmentSetup` adds BK's environment manager for wind globals and the URP depth/opaque textures the pack shaders need; project systems retain lighting ownership.
- MainGame owns excavation and stations. `LakebedSiteSetup` regenerates `MainGameRoot/Environment`, the rim collar, the camp placement and the bedrock (`MainGameSceneBuilder.PlaceBedrock`) from the unmodified Highlands demo into `Assets/Content/Lakebed`; its partials own the lakebed dressing (`.Lakebed`), dig plot ground, band and topsoil with its compared options shown by `TopsoilVariants` (`.DigGround`), the dig boundary options shown by `DigBoundaryMarkers` (`.Boundary`), water shader and materials (`.Presentation`) and detail, caster and visibility settings (`.Performance`). `SunPresentationSetup` owns sky, sun, grading, shadows and reflections. `GroundTextureSetup` configures the dig ground materials that `GroundTriplanar` blends from mesh material weights. `WindowsBuild` always builds MainGame.
- `DiscoveryCatalog` and the `DiscoveryContentSetup` importers (`PhotoRockSetup`, `MineralSetup`, `RetroComputerSetup`) keep item identities separate from prefab art. `DiscoveryField` reserves authored unique envelopes before seeded commons. `BuriedFind` owns one `FindState` record through world, extraction, storage and display; bag collection is common-only.
- `FpsPlayer` owns `FindDetector`; `DiscoveryField.PopulationRevision` invalidates its authored-source cache. `DetectorTargeting` selects by aim alignment within range and returns three signal levels with small angular/range hysteresis, tuned in `EquipmentProgression`. `FindDetector` excludes any exposed or previously observed find using existing `BuriedFind` state. `GameHudView` drives the separate three-bar panel directly; detector state is derived and unsaved.
- `FindExtractionInteraction` owns armed hold targeting in `FpsPlayer`. `SalvageWinch` owns the single guided job; `ExtractionRoutePlanner` searches immutable density incrementally. `WinchRopeView` owns cable/hook presentation, world collision queries and the reusable `RecoveryMarkView` surface glyph; `RopeDynamics` integrates bounded rope particles, distance constraints, momentum-preserving payout/retraction and contact response. Route points seed the cable once; the rim and physical load provide its endpoints. `FindPhysics` yields body control and forwards recovery contacts. `SalvageWinch.Physics` retains the load spring and reel-speed/tension burst; `SalvageWinch.Contacts` gates local breaks through `TerrainVolume`/`ExcavationGrid.RemoveBoxSweep`. `SalvageWinch.Feedback` emits pooled crumb/dust particles after committed breaks. Rope oscillation is transient; the checkpoint retains the accepted route, load pose/velocities and guide progress.
- `SalvageWinchSetup` wires receiving pads and independent `UniqueDisplayStand` sockets for the unique catalog. The winch chooses free arrival space from stored poses; the accepted route retains its destination. Each stand moves the existing stored object into its socket, and recovery validates all authored sockets. `ExtractionSnapshot` shares the whole-world save with terrain and find poses. Source fixture geometry belongs to `art/salvage-winch`, runtime assets/settings to `Content/Salvage`.
- `WorksiteTools` owns the reusable lamp kit, placement previews and projected `WorldMark` stencils. `WorkLamp` owns support release and physical motion; terrain edit bounds trigger support checks. `WorksiteSnapshot` persists equipment with the hole. `WorksiteToolsSetup` wires MainGame and original `art/work-lamps` content; `GamePreferences` preserves lamp occlusion independently of optional sun shadows.
- `ComputerStation` switches the shared terminal from selling to upgrades; `StationTrade` binds trades to inventory/wallet/battery revisions; `EquipmentProgression` owns the shared level ceiling, tool profiles, shovel/drill milestone, capacity increments and price ladder. `ShovelState` owns purchased tool progress; save restore derives its motion from that level.

Update this file only when folder ownership, major system boundaries or scene ownership changes.
